# GraphApp8Pro 持久峰值平滑功能修改计划

## 1. 文档目的

本文档用于指导 GraphApp8Pro 的“持久峰值平滑测试”功能开发，明确：

- 要实现的用户行为；
- 峰值平滑算法及默认参数；
- 需要新增、修改的类和资源；
- 界面、CSV 和 HTML 如何保证使用同一份平滑数据；
- 采集线程、Swing 线程和文件线程之间如何协作；
- 测试步骤、验收标准、风险和回退方案。

本文档只是一份修改计划，不包含业务代码修改。

---

## 2. 已确认需求

### 2.1 核心需求

1. 实时界面新增“持久测试”按钮。
2. 点击按钮后开始一次新的持久峰值测试会话：
   - 清空上一轮持久峰值；
   - 界面峰值位置显示 `--` 或初始化进度；
   - 重新采集多组数据；
   - 计算第一个平滑峰值并开始显示。
3. 初始值生成后，输入信号整体提升 1 dB、2 dB、3 dB 等较小幅度时：
   - 不得因为固定大阈值而完全不更新；
   - 界面峰值应缓慢拉高；
   - CSV 中的峰值也应以完全相同的节奏缓慢拉高。
4. 单个毛刺或偶发尖峰不应明显抬高平滑结果。
5. 信号下降时允许缓慢回落，但回落速度应慢于上升速度，保持“峰值持有”观感。
6. CSV 只保存给人查看的平滑峰值，不把原始峰值混入报告 CSV。
7. 每个测试会话生成一份 CSV 和一份可读取该 CSV 的 HTML 趋势查看器。
8. HTML 默认只绘制 CSV 中的平滑峰值，其曲线必须与测试期间界面显示一致。

### 2.2 数据一致性要求

系统只能存在一个对外发布值：

```text
publishedPeakDbm[channel]
```

同一时刻：

- Swing 界面读取该发布值；
- CSV 写入该发布值；
- HTML 从 CSV 读取该发布值；
- 三者采用相同的一位小数舍入结果。

禁止界面和 CSV 分别重新计算或分别舍入。

### 2.3 本期非目标

本次修改不应：

- 改变 UDP 数据解析协议；
- 改变 PRPS/PRPD 原始图形数据；
- 用平滑峰值替换触发、告警、故障识别所使用的原始峰值；
- 把平滑值写回历史局放事件或现有检测报告数据；
- 自动恢复上一次程序运行留下的持久峰值；
- 把原始峰值写进给人查看的主 CSV；
- 引入联网图表库或新的 Maven 依赖。

## 3. 当前代码链路和接入依据

### 3.1 当前采集链路

当前数据处理链路如下：

```text
GisUDP.run()
  -> 解析每帧 8 通道 × 64 点数据
  -> 限制原始值到 0～4095
  -> GisChannelData.proc1Cycle(dataTemp)
  -> 每通道计算当前周波最大值 i4
  -> 写入 cycleMax[80]
  -> 计算最近 80 周波最大值
  -> 转成 dBm 并写入 GisGraph.amxdBm / PRPDGraph.amxdBm
  -> GisXYZ 主循环触发 guiRefresh()
  -> GisGraph / PRPDGraph 绘制峰值
```

关键位置：

- `main/java/com/Spectrogram/ZmGis8CH/gis_app_8CH/GisUDP.java`
  - UDP 数据解析约在 205～243 行；
  - `gd.proc1Cycle(dataTemp)` 是平滑服务的上游入口。
- `main/java/com/Spectrogram/ZmGis8CH/gis_app_8CH/GisChannelData.java`
  - `proc1Cycle()` 从约 119 行开始；
  - 当前周波峰值 `i4` 在约 155～156 行产生；
  - 80 周波历史峰值在约 346～388 行处理；
  - `prps[i].amxdBm` 在约 388 行赋值。
- `main/java/com/Spectrogram/ZmGis8CH/gis_app_8CH/GisGraph.java`
  - `amxdBm` 字段约在 20 行；
  - 实时图峰值文字约在 744 行绘制；
  - 峰值指示三角形约在 752 行绘制。
- `main/java/com/Spectrogram/ZmGis8CH/gis_app_8CH/PRPDGraph.java`
  - `amxdBm` 字段约在 49 行；
  - 不同 PRPD 绘制模式中存在多处峰值文字和峰值条绘制。
- `main/java/com/Spectrogram/ZmGis8CH/gis_app_8CH/HbDesktopPane.java`
  - 顶部工具栏和连续采集按钮约从 453、510 行开始创建；
  - 新按钮应在该类中接入。

### 3.2 不能直接平均现有 `amxdBm`

现有 `amxdBm` 是最近 80 周波的滑动最大值，相邻两次值可能共享 79/80 的数据。如果直接按每个 UDP 帧平均该值，会产生大量重复样本，曲线虽然看似平滑，但响应时间和统计意义均不可靠。

本功能必须基于非重叠数据组计算：

```text
每 80 个新周波 -> 生成 1 个独立 groupPeakDbm
```

每组结束后清空该组累积器，下一组不得复用上一组周波。

### 3.3 原始值和平滑显示值必须分离

现有 `amxdBm` 还参与部分优先触发和业务判断，因此不能直接覆盖成平滑值。设计上保留：

```text
raw peak               -> 原有 amxdBm，继续用于现有业务
published smooth peak  -> 新增服务维护，只用于持久测试显示和报告 CSV
```

## 4. 总体设计

### 4.1 数据流

```text
当前周波 64 点原始数据
        |
        v
计算当前周波峰值
        |
        +------------------------------> 原有实时峰值/触发/分析逻辑（保持不变）
        |
        v
非重叠 80 周波分组最大值 groupPeakDbm
        |
        v
初始化去极值平均 / 5 组滑动去极值平均
        |
        v
上升、下降非对称慢跟随
        |
        v
不可变 PersistentPeakSnapshot
        |                         |
        v                         v
Swing 界面显示                CSV 异步写入
                                  |
                                  v
                              HTML 读取绘图
```

### 4.2 单一发布快照

每完成一组平滑计算，服务生成一份不可变快照：

```java
PersistentPeakSnapshot {
    long sequence;
    Instant timestamp;
    long elapsedMillis;
    PeakSessionState sessionState;
    double[] publishedDbm;        // 已统一舍入到 1 位小数，对外唯一数据
    boolean[] valid;
    String event;
}
```

要求：

1. `publishedDbm` 在快照创建时统一舍入；
2. 界面和 CSV 均消费同一个快照实例；
3. 内部滤波值继续保留完整 `double` 精度，不使用舍入后的发布值反算；
4. 快照数组必须防止外部修改，可在构造时复制，在访问时返回副本或只提供按通道读取接口。

## 5. 平滑算法详细设计

### 5.1 默认配置

```properties
# 一个基础峰值组包含的电气周波数
group.cycles=80

# 启动后先丢弃的完整组数，避免旧数据和采集启动瞬态
warmup.groups=1

# 第一个平滑峰值所需基础峰值组数
initial.groups=10

# 后续稳健平均的滑动窗口大小
average.groups=5

# average.groups >= 5 时去掉的最高、最低样本数
trim.count=1

# 小幅上升的跟随系数
alpha.rise=0.35

# 下降跟随系数，低于上升系数以形成峰值保持效果
alpha.fall=0.15

# 小于此差值时不更新内部发布值，防止浮点微抖动
display.epsilon.db=0.05

# 仅用于 HTML/CSV 事件标记，不阻止 1/2/3 dB 小变化更新
significant.change.db=3.0

# CSV 写入参数
csv.flush.interval.ms=1000
csv.queue.capacity=1024
csv.max.file.mb=50
```

参数建议保存到用户数据目录中的 `persistent-peak.properties`。文件不存在时使用代码默认值；参数非法时记录警告并回退默认值。

### 5.2 基础峰值组

每通道维护：

```java
int cyclesInCurrentGroup;
int[] currentGroupMaxRaw;
```

每收到一个完整周波：

```java
currentGroupMaxRaw[ch] = Math.max(currentGroupMaxRaw[ch], cyclePeakRaw[ch]);
```

达到 `group.cycles` 后：

1. 使用当前软件已有校准范围和该通道增益转成 dBm；
2. 生成 8 通道 `groupPeakDbm`；
3. 将其交给 `PersistentPeakService`；
4. 将组计数和组最大值全部清零。

点击“持久测试”后必须从 `cyclesInCurrentGroup=0` 开始，不能把点击前的数据纳入新会话。

### 5.3 初始发布值

每通道独立收集 `initial.groups=10` 个有效组峰值。

处理方法：

1. 对 10 个值排序；
2. 去掉最高 1 个和最低 1 个；
3. 对中间 8 个求算术平均；
4. 将结果作为内部 `publishedInternalDbm[ch]`；
5. 创建第一个对外快照。

公式：

```text
initialPeak = mean(sortedSamples[trimCount .. N-trimCount-1])
```

若某通道数据无效，该通道不推进初始化计数，其他通道可继续独立初始化。快照中未准备好的通道写空值，界面显示 `--`。

### 5.4 后续稳健目标值

每通道维护最近 `average.groups=5` 个非重叠组峰值。

每加入一个新组：

1. 对最近 5 个值排序；
2. 去掉最高和最低各 1 个；
3. 对中间 3 个求平均；
4. 得到 `targetDbm[ch]`。

这样可以过滤单个高尖峰或单个低异常点，同时持续存在的 1 dB、2 dB、3 dB 整体变化仍会进入目标值。

### 5.5 上升和下降慢跟随

取消“差值不足 3 dB 就完全不更新”的硬门槛。

每个新目标值到达时：

```java
double error = targetDbm - publishedInternalDbm;

if (Math.abs(error) >= epsilonDb) {
    double alpha = error > 0 ? riseAlpha : fallAlpha;
    publishedInternalDbm += alpha * error;
}
```

默认：

- 上升系数 `0.35`；
- 下降系数 `0.15`；
- 变化小于 `0.05 dB` 才停止继续逼近。

因此：

- 持续提升 1 dB：发布值缓慢提升约 1 dB；
- 持续提升 2 dB：发布值缓慢提升约 2 dB；
- 持续提升 3 dB：发布值缓慢提升约 3 dB；
- 单个尖峰：被 5 组去极值平均剔除；
- 信号回落：比上升更慢地回落。

### 5.6 预期响应时间

以输入突然、持续提升 1 dB 为例：

- 去极值窗口通常在第 2 个新组后开始形成变化；
- 约 3 秒后界面和 CSV 开始出现可见上升；
- 约 11～13 秒达到变化量的 90%；
- 约 13～16 秒显示为完整的约 1.0 dB 提升；
- 输入提升 2 dB、3 dB 时响应时间基本相同，曲线幅度按比例增大。

实际时间与设备同步频率、变化发生在组内的位置有关，应在硬件回放测试后确认。

### 5.7 舍入规则

内部：

```text
publishedInternalDbm = 完整 double 精度
```

对外快照：

```text
publishedDbm = HALF_UP 舍入到 1 位小数
```

建议集中实现：

```java
PeakValueFormatter.roundForPublish(double value)
PeakValueFormatter.formatForCsv(double value)
PeakValueFormatter.formatForUi(double value)
```

其中 UI 和 CSV 必须读取快照中已经舍入的值；格式化方法只能改变字符串形式，不能再次改变数值。

## 6. 会话状态机和按钮行为

### 6.1 会话状态

```text
IDLE
  -> STARTING
  -> WAITING_FOR_ACQUISITION
  -> WARMING_UP
  -> INITIALIZING
  -> RUNNING
  -> FINAL_HOLD
  -> IDLE（下一次启动时重新清空）

任意活动状态
  -> ERROR（文件错误不应停止采集）
```

### 6.2 “持久测试”按钮行为

在 `HbDesktopPane` 顶部工具栏增加 `JToggleButton persistentTestButton`。

建议文字和状态：

| 状态 | 按钮/状态提示 | 峰值显示 | CSV |
|---|---|---|---|
| IDLE | 持久测试 | 原实时峰值 | 未创建 |
| STARTING | 正在创建测试 | `--` | 创建目录和文件 |
| WAITING_FOR_ACQUISITION | 等待采集 | `--` | 只有表头 |
| WARMING_UP | 预热 1/1 | `--` | 不写峰值行 |
| INITIALIZING | 初始化 4/10 | `--` | 不写峰值行 |
| RUNNING | 持久测试中 | 平滑峰值 | 每组写一行 |
| FINAL_HOLD | 结果已保持 | 最终平滑峰值 | 已关闭 |
| ERROR | CSV异常，峰值仍显示 | 平滑峰值 | 停止或降级写入 |

按钮操作：

1. 第一次点击：
   - 异步创建会话目录；
   - 清空平滑服务状态；
   - 设置实时图为持久显示模式；
   - 不自动启动 UDP 连续采集；
   - 如果设备未采集，进入等待状态。
2. 测试中再次点击：
   - 停止接收新的平滑组；
   - 刷新并关闭 CSV；
   - 界面继续显示最终平滑值；
   - 状态进入 `FINAL_HOLD`。
3. 在 `FINAL_HOLD` 状态再次启动：
   - 创建新的会话目录和 CSV；
   - 清空旧值；
   - 重新初始化。

### 6.3 参数改变行为

测试过程中发生以下事件时，现有平滑值已不可直接比较：

- 通道增益改变；
- dBm 校准范围改变；
- 硬件模式改变；
- 通道重新连接后测量基准改变。

处理规则：

1. 清空受影响通道的组数据和滑动窗口；
2. 该通道重新进入预热和初始化；
3. CSV 的该通道暂时写空值；
4. `event` 列写入 `CONFIG_RESET:CHn`；
5. HTML 在重置处断线，不把重置前后直接连接成连续物理变化。

## 7. 线程模型

### 7.1 采集线程

`GisUDP` 线程继续负责接收数据，并同步调用 `GisChannelData.proc1Cycle()`。

采集线程只允许执行：

- 每周波峰值累积；
- 小数组排序和滤波计算；
- 生成不可变快照；
- 将快照无阻塞地放入 CSV 队列；
- 将 UI 更新任务提交给 EDT。

禁止在采集线程：

- 创建目录；
- 打开浏览器；
- 直接进行可能阻塞的 CSV 磁盘写入；
- 弹出 Swing 对话框；
- 等待 CSV 线程结束。

### 7.2 Swing EDT

所有按钮文字、颜色、进度、图形显示状态的变化必须通过：

```java
SwingUtilities.invokeLater(...)
```

执行。

EDT 消费快照后：

1. 将同一快照应用到 8 个实时 `GisGraph` 和 `PRPDGraph`；
2. 更新初始化进度或运行状态；
3. 调用必要的 `repaint()`；
4. 不执行文件写入。

### 7.3 CSV 写入线程

新增一个单写入线程：

- 有界队列容量默认 1024；
- 每个快照最多入队一次；
- 一个线程按 `sequence` 顺序写入；
- 每 1 秒 flush；
- 停止会话时 flush、close，并在后台等待完成；
- 队列满时不得阻塞 UDP，应累计 `droppedCsvSnapshots` 并在界面提示；
- JVM 正常退出前最多等待 2 秒完成关闭。

### 7.4 服务并发控制

按钮的 `startSession/stopSession` 来自 EDT，`acceptCyclePeaks` 来自 UDP 线程。建议：

- 状态切换使用短小的 `synchronized` 临界区；或
- 使用不可变会话上下文加 `AtomicReference`；
- 不在锁内执行目录创建、文件打开、flush、close；
- 每个会话携带唯一 `sessionId`，旧会话迟到的写入任务必须被丢弃，不能写进新文件。

## 8. 文件修改清单

## 8.1 新增 Java 类

新增目录均位于：

```text
main/java/com/Spectrogram/ZmGis8CH/gis_app_8CH/
```

### A. `PersistentPeakConfig.java`

职责：

- 定义上述默认参数；
- 从用户数据目录加载 `persistent-peak.properties`；
- 对参数进行范围校验；
- 参数缺失或非法时使用默认值；
- 提供不可变 getter，不允许运行过程中被其他类随意修改。

至少校验：

```text
group.cycles >= 1
warmup.groups >= 0
initial.groups >= 3
average.groups >= 3 且最好为奇数
trim.count >= 0
2 * trim.count < initial.groups
2 * trim.count < average.groups
0 < alpha.rise <= 1
0 < alpha.fall <= 1
alpha.fall <= alpha.rise
0 <= display.epsilon.db < 1
csv.queue.capacity >= 16
```

### B. `PersistentPeakSnapshot.java`

职责：

- 保存一次对外发布的 8 通道平滑峰值；
- 统一完成一位小数舍入；
- 提供时间戳、序号、状态、有效标记和事件；
- 保持不可变；
- 同时供 UI 和 CSV 消费。

### C. `PeakValueFormatter.java`

职责：

- 提供统一的 HALF_UP 一位小数舍入；
- UI 使用当前语言所需的显示形式；
- CSV 固定使用 `Locale.ROOT` 和小数点 `.`；
- 对 NaN/无效值返回空 CSV 单元格和 UI `--`。

### D. `PersistentPeakService.java`

职责：

- 管理 8 通道独立状态；
- 管理整个测试会话状态机；
- 接收每周波峰值；
- 形成非重叠 80 周波基础组；
- 执行预热、初始化去极值平均、5 组滑动去极值平均；
- 执行上升 0.35、下降 0.15 的慢跟随；
- 生成不可变快照；
- 将同一个快照分别投递给 UI 和 CSV；
- 处理暂停、数据中断、重连、参数重置和停止会话。

建议公开接口：

```java
void startSession(PersistentPeakSession session);
void stopSession();
void acceptCyclePeaks(int[] rawCyclePeaks, PeakMeasurementContext context);
void resetChannel(int channel, String reason);
PeakSessionState getState();
PersistentPeakSnapshot getLastSnapshot();
void shutdown();
```

### E. `PersistentPeakCsvWriter.java`

职责：

- 创建会话 CSV；
- 写入 UTF-8 BOM 和表头；
- 异步顺序写入快照；
- 定时 flush；
- 文件达到上限后安全轮转；
- 停止时关闭；
- 暴露写入失败、队列积压和丢弃计数。

### F. `PeakTrendHtmlGenerator.java`

职责：

- 在会话目录生成 `peak-trend.html`；
- 从 classpath 复制自包含模板；
- 不联网、不引用 CDN；
- 必要时在 HTML 中写入本次会话参数说明。

### G. 可选：`PersistentPeakSession.java`

若不希望把路径和会话信息放入 Service，可单独封装：

```java
sessionId
startTime
outputDirectory
csvPath
htmlPath
configSnapshot
```

## 8.2 新增资源文件

## 9. CSV 设计

### 9.1 输出位置

Windows 默认：

```text
%LOCALAPPDATA%\GraphApp8Pro\persistent-peak\yyyyMMdd_HHmmss\
```

目录内容：

```text
20260820_112800\
├── peaks.csv
├── peak-trend.html
└── session.properties
```

如果 `LOCALAPPDATA` 不存在，回退到：

```text
${user.home}\.graphapp8pro\persistent-peak\...
```

不得默认写到程序安装目录，避免安装在只读目录时失败。

### 9.2 主 CSV 格式

采用宽表，一行代表一个发布时刻：

```csv
time,elapsed_seconds,UHF-1_dBm,UHF-2_dBm,AE-1_dBm,AE-2_dBm,HFCT-1_dBm,HFCT-2_dBm,Spare-1_dBm,Spare-2_dBm,event
2026-08-20 11:28:05.123,17.1,-34.2,-35.1,-42.6,-41.8,-38.0,-37.5,-50.2,-49.8,
2026-08-20 11:28:06.456,18.4,-34.1,-35.1,-42.6,-41.8,-38.0,-37.5,-50.2,-49.8,
```

规则：

1. UTF-8 BOM，便于 Windows Excel 正确识别；
2. Windows 换行 `\r\n`；
3. 时间固定到毫秒；
4. dBm 固定一位小数和 `.` 小数点；
5. 一个完整基础组产生一行；
6. 即使发布值没有变化，也重复写当前值，以表达持续时间；
7. 初始化完成前不写数值行，避免用 `-80 dBm` 冒充数据；
8. 某通道重置或无效时对应单元格留空；
9. 数据中断时不重复旧值，恢复后通过时间差和 `event` 表达断点；
10. `event` 可写：
    - `SIGNIFICANT_RISE:CH1`；
    - `SIGNIFICANT_FALL:CH2`；
    - `DATA_GAP`；
    - `CONFIG_RESET:CH3`；
    - `CSV_QUEUE_DROPPED:n`。

### 9.3 会话参数文件

`session.properties` 保存本次实际使用参数：

```properties
session.id=20260820_112800
start.time=2026-08-20T11:28:00.000+08:00
group.cycles=80
warmup.groups=1
initial.groups=10
average.groups=5
trim.count=1
alpha.rise=0.35
alpha.fall=0.15
display.epsilon.db=0.05
significant.change.db=3.0
```

报告分析时必须知道当次参数，不能只依赖程序当前配置。

### 9.4 文件轮转

当 `peaks.csv` 达到默认 50 MB：

```text
peaks.csv
peaks_002.csv
peaks_003.csv
```

每个文件均写完整表头。HTML 支持一次选择多份同会话 CSV，并按时间合并。

## 11. 异常和边界处理

### 11.1 无采集数据

- 按钮进入“等待采集”；
- 峰值显示 `--`；
- CSV 只有表头；
- 不启动虚假定时数据。

### 11.2 UDP 中断或帧号跳变

- 当前未完成的 80 周波组作废；
- 平滑值在界面保持，但同时显示“数据中断”；
- 中断期间不写重复 CSV 行；
- 恢复后先预热 1 组，再继续或重新初始化；
- CSV 写入 `DATA_GAP`。

### 11.3 饱和数据

原始 ADC 峰值达到 4095 时：

- 本组可参与平滑，但必须记录一次饱和事件；
- 如果连续饱和，应在界面和 HTML 显示警告；
- 不允许把 4095 以上数据静默当作普通值。

### 11.4 CSV 目录不可写

- UI 显示明确错误路径和原因；
- 平滑界面可以继续工作；
- 不得阻塞或停止 UDP 采集；
- 用户停止时安全清理写入线程；
- 不循环弹出对话框。

### 11.5 CSV 队列满

- UDP 线程不等待；
- 累计丢弃数量；
- UI 显示“CSV记录不完整”；
- 下一次成功写入时将丢弃数量写入 `event`；
- 验收测试要求正常环境下丢弃数为 0。

### 11.6 多次快速点击按钮

- STARTING 时暂时禁用按钮；
- 同一时间最多存在一个活动会话；
- 连续点击不得创建两个 CSV 写入线程；
- 旧会话关闭完成前，新会话使用不同 `sessionId` 和目录；
- 迟到快照不能写进新会话。

## 13. 单元测试计划

### 13.1 算法测试

1. **恒定信号**
   - 输入恒定 `-40 dBm`；
   - 初始化值应为 `-40.0 dBm`；
   - 继续输入后不应产生可见抖动。
2. **初始化去极值**
   - 10 组中加入一个极高值和一个极低值；
   - 初始值应由剩余 8 组决定。
3. **单个尖峰**
   - 稳定值中插入一个高尖峰；
   - 5 组去极值窗口应剔除尖峰；
   - 发布值变化不得超过 0.1 dB。
4. **持续提升 1 dB**
   - 发布值必须单调缓慢上升；
   - 最终收敛到原值约 `+1.0 dB`；
   - 不能因 `significant.change.db=3` 而停止更新。
5. **持续提升 2 dB、3 dB**
   - 响应曲线时间常数与 1 dB 基本相同；
   - 最终幅度分别约为 `+2.0`、`+3.0 dB`。
6. **信号回落**
   - 回落速度应慢于同幅度上升速度；
   - 最终仍应收敛到新稳定值。
7. **阈值附近微抖动**
   - 变化小于 `0.05 dB` 不产生发布更新；
   - 不出现来回跳动或 NaN。
8. **通道独立性**
   - 一个通道异常、重置或未就绪，不影响其他通道。
9. **重新开始**
   - 新会话不得带入旧组、旧滑动窗口和旧平滑值。
10. **舍入一致性**
    - 快照、UI字符串和CSV字符串对应同一一位小数值；
    - 内部滤波仍保留完整精度。

### 13.2 CSV 测试

1. UTF-8 BOM 和表头正确；
2. 8 通道列顺序固定；
3. 一位小数且不受中文系统小数格式影响；
4. 初始化前无伪数据；
5. 空通道输出空单元格；
6. 停止后所有队列数据已 flush；
7. 轮转文件有完整表头；
8. 文件不可写时服务不死锁；
9. 并发停止/启动不串会话；
10. CSV 读取回来的值逐行等于快照发布值。

### 13.3 HTML 测试

1. 能读取 BOM CSV；
2. 能处理空值和数据断点；
3. 8 个通道可独立显示/隐藏；
4. 鼠标提示与 CSV 一位小数完全一致；
5. 不联网时完整可用；
6. 多个轮转文件可以按时间合并；
7. 错误行提示行号，其他有效行仍可绘制。

## 16. 风险和控制措施

| 风险 | 影响 | 控制措施 |
|---|---|---|
| 直接平均现有 80 周波滑动最大值 | 样本重复、时间响应失真 | 使用非重叠 80 周波组 |
| 直接覆盖 `amxdBm` | 影响触发和业务判断 | 新增独立发布值，只改显示路径 |
| UI 与 CSV 分别计算 | 数值不一致 | 使用同一个不可变快照 |
| 两处分别格式化/舍入 | 最后一位不一致 | 快照创建时统一舍入 |
| CSV 在 UDP 线程写磁盘 | 丢包、界面卡顿 | 有界队列和单独写线程 |
| 单个尖峰抬高报告 | 曲线误判 | 5 组去掉最高/最低后平均 |
| 3 dB 硬门槛 | 1/2 dB 变化永不显示 | 取消硬门槛，3 dB 只标记事件 |
| 增益改变被当成信号变化 | 报告产生假阶跃 | 通道重置并在 CSV 标记 |
| 断网期间重复旧值 | 报告伪装成连续采集 | 停止写行并在恢复处断线 |
| 程序直接 `System.exit` | CSV 尾部损坏 | 统一关闭入口、flush 后退出 |
| 旧外部语言文件缺少新键 | 按钮文字为空 | 新键按项回退默认文案 |
| 历史图复用实时图类 | 历史显示被污染 | 持久模式默认关闭且实例级保存 |

## 17. 回退方案

1. 持久功能默认仅在按钮启动后生效；
2. 未启动时所有绘图继续读取原始 `amxdBm`；
3. 平滑服务异常时：
   - 停止本次 CSV；
   - 将按钮标记为异常；

4. 新增代码按独立类组织，回退时可移除按钮接线和显示 getter，不需要修改 UDP 协议；
5. 建议将以下内容拆成独立提交，便于逐项回滚：
   - 算法和测试；
   - 采集接入；
   - UI 接入；
